# Практичне заняття 2 — Налаштуйте Claude для CampusDesk

**Мова:** українська · [English](../02-project-setup.md)

**Час:** 50–70 хвилин  
**Коли:** після лекції 1, бажано після практичного заняття 1  
**Працюйте в:** `practice/starter-campusdesk/`

## Мета

Створити файл `CLAUDE.md`, який не соромно закомітити, налаштувати gitignore для локальних файлів і вперше випробувати команди `/init` та `/context`. Інший студент має без проблем клонувати цю теку й отримати таку саму поведінку агента.

## Завдання

### 1. Гігієна Git

Навіть якщо ця тека ще не є окремим git-репозиторієм, ви все одно можете додати правила ігнорування файлів до `.gitignore` курсу або створити тут локальний файл ігнорування.

Переконайтеся, що ці файли не потраплять у коміт, коли ви почнете працювати з Git:

```
CLAUDE.local.md
.claude/settings.local.json
.venv/
```

### 2. `/init`

```bash
cd practice/starter-campusdesk
claude
```

Запустіть `/init`. Нехай агент згенерує чернетку `CLAUDE.md`. **Після цього почистьте її.**

Залиште:

- команди install, run, test і lint
- інформацію про те, де знаходяться routes, models та store
- факт, що in-memory store скидається після перезапуску застосунку
- фразу на кшталт «завдання готове, коли pytest та ruff проходять успішно; покажи вивід»
- посилання на `docs/product.md` та `docs/architecture.md`

Видаліть:

- загальні поради на кшталт «пишіть чистий код»
- екскурсію кожною окремою функцією
- продубльований вміст README

Ціль: **суттєво менше ніж 200 рядків**. Орієнтуйтеся десь на 40–80.

### 3. Підключення документації

У `CLAUDE.md` імпортуйте два короткі документи:

```markdown
Продукт: @docs/product.md
Архітектура: @docs/architecture.md
```

Ці файли досить малі, тому їх можна додавати до контексту кожної сесії. (На лекції 4 ми обговоримо, чому так не варто робити з великими вікі-системами.)

### 4. Локальний файл (необов’язково)

Створіть файл `CLAUDE.local.md` із чимось, що важливо особисто вам, наприклад: «Я віддаю перевагу pytest -q». Переконайтеся, що цей файл додано до gitignore.

### 5. Перевірте, чи все завантажилося

Виконайте `/clear` або почніть нову сесію. Запустіть `/context`.

**Пройдено, якщо:** `CLAUDE.md` з’являється серед файлів Memory. Якщо ви імпортували документацію, вона теж має відображатися.

### 6. Перевірка поведінки

Почніть нову сесію, **не** у режимі Plan (схвалювати зміни дозволяється):

```text
Яку команду треба запустити перед тим, як сказати, що завдання виконано?
Відповідай за інструкціями проєкту, а не загальними порадами.
```

**Пройдено, якщо:** агент цитує `pytest` і `ruff` з вашого файлу.

Якщо він починає розповідати про «найкращі практики» без згадок цих команд, ваш `CLAUDE.md` занадто розмитий або просто не завантажився. Виправте це й повторіть запит у **новій** сесії (пам’ять завантажується на старті).

### 7. `/doctor`

Запустіть `/doctor`. Застосовуйте лише ті виправлення, які мають сенс. Слідкуйте, щоб ця команда знову не роздула ваш `CLAUDE.md`.

## Результат

- Файл `CLAUDE.md` у теці стартового застосунку.
- Знімок екрана або скопійований текст розділу Memory з виводу `/context`.
- Нотатка: один рядок, який ви видалили під час чистки після `/init`, і коротке пояснення чому.

## Завдання із зірочкою

Додайте `~/.claude/CLAUDE.md` (на рівні користувача) з вашими особистими вподобаннями. За допомогою `/context` переконайтеся, що завантажилися **обидва** файли — і користувацький, і проєктний. Факти, специфічні для проєкту, тримайте виключно у файлі **проєкту**, щоб ваші колеги теж мали до них доступ.

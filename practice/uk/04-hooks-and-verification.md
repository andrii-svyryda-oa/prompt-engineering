# Практичне заняття 4 — Хуки та цикл перевірки

**Мова:** українська · [English](../04-hooks-and-verification.md)

**Час:** 60–90 хвилин  
**Коли:** після лекції 2  
**Залежить від:** практичних занять 2–3

## Мета

Зробити цикл «написати код → запустити перевірки → виправити» **механічним**. Ви створите хук (або Stop-перевірку), щоб Claude не міг заявити про готовність завдання, поки ruff чи pytest підсвічуються червоним.

Точний формат JSON для хуків може змінюватися в різних версіях Claude Code. **Попросіть Claude згенерувати чернетку хука**, а потім перевірте результат за допомогою `/hooks`.

## Безпека

Працюйте виключно в теці `practice/starter-campusdesk`. Не створюйте хуки, що виконують `rm`, очищають мережеві налаштування або діють за межами цієї теки.

## Завдання

### 1. Ручний цикл один раз (поки без хука)

У новій сесії (режим **Accept edits**):

```text
Не додавай нових функцій.
Запусти pytest -q та ruff check . і покажи результати виконання.
```

Переконайтеся, що обидві перевірки на стартовому застосунку пройшли успішно. Якщо це не так, спершу виправте своє середовище розробки.

### 2. Попросіть Claude написати PostToolUse хук

```text
Додай хук проєкту у .claude/settings.json, який запускатиметься після дій Edit або Write
для файлів Python. Хук має виконувати ruff check для зміненого файлу або всього проєкту.
Зроби так, щоб вивід був коротким. Використовуй змінну CLAUDE_PROJECT_DIR. Зроби його сумісним із Windows, якщо це можливо.
Після цього розкажи мені, як перевірити його за допомогою /hooks.
Не додавай жодних інших хуків.
```

Перегляньте згенерований JSON. Ви маєте розуміти, як працює `matcher` і `command`. Якщо команда виглядає як скрипт на 40 рядків, що повністю виводить вміст файлів — попросіть спростити її.

### 3. Підтвердження реєстрації хука

Виконайте:
`/hooks`

**Пройдено, якщо:** ви бачите свій PostToolUse хук (або його аналог) у списку. Якщо його немає — JSON збережено не в тому файлі або він містить синтаксичні помилки. Команда `/doctor` може допомогти знайти проблему.

### 4. Протестуйте хук

Попросіть Claude навмисно додати помилку, щоб перевірити лінтер:

```text
У файлі app/main.py додай невикористану змінну unused_course_hook_probe = 1,
і одразу зупинись.
```

Після редагування файлу має автоматично запуститися хук. У транскрипті ви повинні побачити скаргу від ruff.

Потім напишіть:

```text
Видали цю невикористану змінну. Поведінку застосунку не змінюй.
Запусти pytest -q та ruff check . Покажи вивід.
```

**Пройдено, якщо:** тестова змінна зникла, а обидві перевірки стали зеленими.

### 5. Stop-перевірка (виберіть один варіант)

**Варіант A — хук Stop:** Попросіть Claude додати хук Stop, який запускає `pytest -q` і скасовує зупинку, якщо тести падають. Будьте обережні: зламаний хук Stop дуже дратує. Якщо ви застрягли — запустіть `/hooks` і видаліть його з налаштувань.

**Варіант B — лише промпт (наприклад, якщо хуки заблоковані на навчальних комп'ютерах):** Додайте це у свій `CLAUDE.md` і в skill `/verify-change`:

```text
У цій сесії ніколи не кажи, що роботу завершено, без успішного проходження pytest -q та ruff check .
```

Потім проведіть негативний тест: попросіть агента «завершити роботу», коли тести ще не запускалися, і подивіться, чи запустить він їх усе одно.

### 6. Запишіть промпт внутрішнього циклу у свою шпаргалку

Ви будете постійно використовувати цей промпт починаючи з 5-го практичного заняття:

```text
Напиши код, а потім запусти pytest -q та ruff check .
Якщо щось падає, виправ і запусти знову.
Не зупиняйся, доки обидві перевірки не стануть зеленими, або поки не назвеш конкретний блокер.
Покажи докази.
```

## Результат

- Diff файлу `.claude/settings.json` (та будь-якого створеного скрипта для хука).
- Скопійований вивід команди `/hooks`.
- Стан до/після додавання тестової змінної.
- Інформація про те, який варіант заборони зупинятися з помилками ви обрали (A чи B).

## Можливі проблеми

| Проблема | Що робити |
| --- | --- |
| Хук ніколи не спрацьовує | Неправильний `matcher`; налаштування не завантажилися (перезапустіть сесію). |
| Хук засмічує контекст | Друкуйте лише один рядок результату, а не повний JSON від ruff. |
| Команда падає на Windows | Використовуйте `python -m ruff` або PowerShell-скрипт `.ps1` у `.claude/hooks/`. |
| Нескінченний цикл Stop | Видаліть хук. Звісно, існує ліміт спроб, але не варто зловживати цією механікою. |

## Завдання із зірочкою

Додайте PreToolUse хук із забороною на запис у файл `.env`, навіть якщо в CampusDesk його ще не існує. Доведіть, що він працює: попросіть Claude створити `.env` із фейковим секретом — дію має бути заблоковано.

Лекція 2

Як Claude читає проєкт

CLAUDE.md, пов’язані документи, rules, skills, hooks — і порядок налаштування, який не топить модель.

Конспект: lectures/uk/02-project-memory-and-setup.md · English

Сьогодні

Шість речей, з якими варто вийти

  1. Сесія не порожня, коли ви друкуєте «привіт». Системний промпт, кореневий CLAUDE.md, rules без scope, описи skills і імена MCP уже у вікні. Читання, path-scoped rules, тіла skills і вивід hooks накопичуються пізніше.
  2. Проза навчає. Settings налаштовують. Hooks примушують. CLAUDE.md — порада в markdown, яку модель може ігнорувати. settings.json — механіка. Якщо вам потрібно «cannot rm -rf», це hook або deny — не курсив.
  3. Напишіть короткий, перевірюваний CLAUDE.md і закомітьте його. Кладіть факти, яких код не скаже: команди run/test/lint, менеджер пакетів, куди класти новий код, always/never, специфічні для проєкту. Ціль — менше ~200 рядків. Розмите «будьте охайними» сюди не належить.
  4. @ у CLAUDE.md — податок на кожну сесію. Імпорти розгортаються на старті. @ в одному промпті сплачується один раз. Не імпортуйте вікі. Імпортуйте коротку архітектурну нотатку — або лише згадайте шлях.
  5. Обирайте шар: завжди / іноді / обов’язково. Завжди істинне й коротке → CLAUDE.md. Завжди істинне лише в app/ → path-scoped rule. Багатокрокове й рідкісне → skill. Має статися, навіть якщо Claude забуде → hook.
  6. Порядок setup, який зупиняється, коли наступний шар не має тригера. Спочатку чесний README і тести. /init, потім обріжте. /context, щоб довести, що завантажилось. Allowlist для pytest і ruff. Додавайте rules, один skill, один hook лише коли є повторювана помилка, яку треба запобігти.

Тест для кожного рядка

Чи призведе видалення цього до повторюваної помилки?

Якщо ні — не додавайте. Пастка — збирати кожну фічу: файли пам’яті, rules, skills, hooks, plugins, субагенти, MCP. Вам не потрібні всі вони в перший день. Вам потрібен правильний шар для кожного виду знань.

Довгі інструкції не сильніші. Їх легше ігнорувати.

Мапа

Як виглядає справжній репозиторій

Claude Code дивиться на робочу директорію і вашу user-папку. Командні файли комітять. Ваш смак лишається в gitignore.

CLAUDE.md                 # команда, комітити
CLAUDE.local.md           # ви, gitignore
.mcp.json                 # сервери, без секретів
.claude/
  settings.json           # permissions, hooks — комітити
  settings.local.json     # ваші allowlists — gitignore
  rules/*.md
  skills/*/SKILL.md

Файли на рівні користувача живуть у ~/.claude/. Користуйтеся ними для свого смаку, не для архітектури команди.

Сплачено до «привіт»

Системний промпт · кореневий CLAUDE.md і rules без scope · автопам’ять (з лімітом) · описи skills, не тіла · імена MCP (схеми часто пізніше).

Потім росте

Сплачено, поки працює

Кожне Read · path-scoped rules і вкладені CLAUDE.md, коли відкривають відповідні файли · тіла skills на / або збіг · вивід hooks після правок.

Звичка

/context — як перевірити, що завантажилось

Він показує діаграму того, що насправді зайняло вікно — не те, що ви сподівались завантажити. Запускайте після /init і щоразу, коли агент починає ігнорувати правило, яке ви точно написали.

  • Якщо CLAUDE.md немає серед Memory files, ви в неправильній директорії або файл названо неправильно.
  • Якщо Memory files — 800 рядків, ви імпортували забагато. Обріжте або перенесіть розділи в path-scoped rules.
  • Запускайте всередині папки проєкту, не в корені курсу.

CLAUDE.md

Постійні інструкції, кожна сесія

Ви його пишете. Це заміна повторювати себе. Файли конкатенуються — вони не перевизначають одне одного як CSS. Суперечності змушують Claude обирати навмання.

ScopeДеХто
User~/.claude/CLAUDE.mdВи, усі проєкти
Project./CLAUDE.mdКоманда — комітьте
Local./CLAUDE.local.mdВи, цей репозиторій — gitignore
Nestedpackage/CLAUDE.mdЗавантажується, коли працюєте в цьому піддереві

Claude також піднімається вгору по дереву. Запуск у apps/api/ може завантажити три файли. У монорепозиторії це потужно і шумно.

Пишіть це

Факти, яких код чітко не скаже

Кладіть те, що Claude не може надійно вивести. Залишайте за бортом туторіали, каталоги всіх endpoints і «будьте професійними».

Кладіть

  • Як запускати, тестувати, лінтити, перевіряти типи
  • Менеджер пакетів (pnpm vs npm)
  • Always / never, специфічні для проєкту
  • Куди класти новий код (routes vs store)
  • Підводні камені: in-memory store, спільний стан тестів

Залишайте за бортом

  • Переказ README
  • Усю архітектурну вікі
  • «Пишіть чистий код»
  • Усе, чим має володіти path-scoped rule або skill

Ціль — менше ~200 рядків. Якщо видалення рядка не спричинить помилку — видаліть його.

Конкретність

Перевірюване перемагає ввічливе

Модель добре вміє звучати так, ніби послухалась. Дайте їй команду, яку можна запустити, і вивід, який треба показати.

Розмито

«Протестуйте зміни.» «Форматуйте правильно.» «Нічого не зламайте.» Claude напише впевнений абзац і зупиниться.

Перевірюване

«Перед «готово»: pytest і ruff check .. Покажіть останні рядки виводу. Не кажіть готово без них.»

/init

Згенеруйте, потім обріжте

/init чернетить CLAUDE.md з репозиторію. Корисно як перший прохід. Часто задовгий — каталогізує файли замість назвати кілька фактів, що запобігають помилкам.

  • Залиште команди, розкладку, підводні камені.
  • Решту видаліть. Потім запустіть /context і /doctor.
  • /doctor позначить очевидне: відсутні файли, погані назви, секрети не там.

Пов’язані документи

@path у CLAUDE.md сплачується кожну сесію

Імпорти розгортаються на старті. Вкладені стрибки обмежені. Зворотні лапки залишають @README літеральним текстом замість імпорту.

See @README.md for how to run.
Architecture: @docs/architecture.md

Кожну сесію

@ всередині CLAUDE.md — файл у вікні навіть для «перейменуйте цю змінну».

Цього разу

@docs/specs/SPEC-001.md у промпті — податок на це завдання, потім може піти.

Не імпортуйте вікі. Імпортуйте коротку архітектурну нотатку — або лише згадайте шлях, щоб Claude міг відкрити його, коли завдання цього потребує.

Rules

.claude/rules/ розділяє теми

Rules без scope завантажуються на старті — той самий податок, що й CLAUDE.md. Path-scoped rules завантажуються, коли читають відповідні файли; так ви тримаєте стиль Python поза сесією лише з markdown.

---
paths:
  - "app/**/*.py"
  - "tests/**/*.py"
---
# Keep handlers thin. Tests ship with endpoints.

Одна тема на файл. Якщо два rules суперечать, Claude обирає навмання — як і зі складеними файлами CLAUDE.md.

Skills

Процедури, що чекають, доки знадобляться

Папка плюс SKILL.md стає /folder-name. Claude бачить опис одразу (дешево). Тіло завантажується на / або коли завдання збігається (сплачено тоді).

Добрий skill

«Завершити зміну»: запустити pytest і ruff, показати вивід, оновити статус специфікації, не вигадувати скоуп.

Поганий skill

Плейбук на 2 000 рядків, що переказує вікі. Кладіть важливі рядки нагорі — compaction може залишити лише початок.

Старі .claude/commands/*.md ще працюють. Нова робота — через skills.

Оберіть шар

Чотири домівки для знань

Якщо покладете багатокроковий ритуал у CLAUDE.md, ви платите за нього на кожному перейменуванні. Якщо тверде правило безпеки лише в прозі — його проігнорують у зайнятий день.

Hooks

Поради необов’язкові. Hooks — ні.

Hook — це команда, яку продукт запускає на події. Вивід може потрапити в розмову — тримайте його коротким. Лог на 5 000 рядків після кожної правки — так ви отруюєте вікно.

ПодіяТипове застосування
PreToolUseБлокувати rm -rf, блокувати запис у .env
PostToolUseЗапустити ruff після Edit/Write — короткий підсумок, не весь файл
StopВідмовити в «готово», якщо pytest червоний

/hooks — що насправді зареєстровано. JSON на диску — намір. Якщо вони розходяться, довіряйте живій панелі.

Gitignore

Пам’ять команди комітять. Секрети — ні.

CLAUDE.local.md
.claude/settings.local.json
  • Ніколи не комітьте токени, API-ключі чи .mcp.json, у який вшиті секрети.
  • Командні CLAUDE.md, .claude/settings.json, rules і skills варто комітити, щоб наступний інженер отримав той самий цикл.
  • Ваш allowlist для pytest може лишатися локальним, якщо команда ще не домовилась.

Не встановлюйте кожну фічу, бо слайд її перелічив. Кожен крок має запобігати помилці, яку ви вже бачили, або яку цей репозиторій точно спричинить.

Форма CampusDesk

CLAUDE.md, який варто комітити

Такий короткий файл запобігає повторюваним помилкам, не оподатковуючи кожне перейменування.

## Commands
pytest
ruff check .

## Architecture
routes: app/main.py
rules: app/store.py

## Done means
pytest and ruff are green.
Show the output.

Діагностика

Коли «воно не дотримується правил»

Зазвичай файл не завантажено, він похований, або правило було лише порадою. Перевірте живий продукт, перш ніж переписувати абзац.

  • /context — завантажилось? 800 рядків Memory files?
  • /skills — неправильна назва папки, тож / не збігається?
  • /hooks — JSON на диску, але нічого не зареєстровано?
  • Небезпечна дія все одно відбувається → hook або deny, не ще одне речення курсивом

Далі

Лекція 3 — MCP, режими, команди

Додаткові руки для Jira. Режими дозволів. Slash-команди, які ви справді натискатимете. Питайте живий продукт — /mcp, /context, /permissions — а не блог минулого тижня.

Після цієї лекції розкладіть тематичні настанови в rules і skill, потім додайте hook перевірки, щоб «готово» не було лише абзацом.

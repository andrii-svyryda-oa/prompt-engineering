Лекція 1

Від мовних моделей до агентів програмування

Що таке LLM, що таке агент і що Claude Code насправді вміє в репозиторії.

Конспект: lectures/uk/01-llms-agents-capabilities.md · English

Сьогодні

Шість речей, з якими варто вийти

  1. Чесна модель LLM — без містики. Вона передбачає наступний токен із тексту, який уже є у вікні. Вправність — побічний ефект хорошого передбачення тексту, а не прихований «модуль розуміння». Це не база даних вашої компанії і не джерело істини.
  2. Чому чатбот — це не агент. Чатбот лише повертає текст; ви копіюєте його, запускаєте тести й вставляєте помилки. Агент — та сама модель з інструментами: вона може читати файли, запускати команди, бачити результати й продовжувати без вас як рук.
  3. Цикл, який завершує роботу: зібрати → діяти → перевірити → повторити. Агенти зупиняються, коли робота виглядає готовою. Спроєктуйте завдання так, щоб перевірка (pytest, ruff, збірка, скріншот) могла повернути pass або fail без того, щоб ви дивились кожен рядок.
  4. Конкретне меню того, що Claude Code вміє в репозиторії. Дослідити без правок, імплементувати зі специфікації, виправити баг із симптому, рефакторити за наявним патерном, прогнати цикл тестів/лінтерів і пізніше торкнутися git і Jira через інструменти — меню, а не обіцянка.
  5. Що все одно лишається за вами, конкретно. Архітектурні компроміси, шкода користувачам, секрети, запис у production, merge у main і те, чи була специфікація правильною. «Never delete the database» англійською — це прохання; hook або відсутній інструмент — це примус.
  6. Як говорити з ним у перший день, щоб цикл міг закритися. Назвіть файл і HTTP-контракт. Вкажіть через @path. Визначте «готово» як тести + лінтери. Відділіть дослідження від правок. Просіть вивід команд. Переривайте й перенаправляйте замість починати спочатку.

Визначення

LLM передбачає наступний токен

Велика мовна модель перетворює текст, який уже бачила, на наступний шматок тексту — токен — потім наступний, потім наступний. Токен — одна одиниця: іноді слово, іноді частина слова, іноді def або =>. Користь — побічний ефект хорошого передбачення тексту, зокрема великої кількості вихідного коду.

def add(a, b):
    return a + b
def add ( a , b ): return a + b

Приблизний поділ, для навчання — не дамп токенізатора. Одна коротка функція вже близько десятка токенів. Файл на 400 рядків або довгий traceback pytest — тисячі.

Що з цього випливає

Генератор — не джерело істини

Залиште цей список. Він знадобиться, коли демо виглядатиме магічним.

Це єЦе не єТож не очікуйте
Генератор, навчений на великій кількості тексту й коду База даних вашої компанії Що вона «вже знає» ваші сервіси, ID тікетів чи рішення минулого тижня
Обмежена вікном токенів Компілятор чи запускач тестів Що текст, схожий на команду, — це та сама команда, яку запустили
Часто вправна і часто корисна Детермінована Що той самий промпт двічі дасть ту саму відповідь
Може користуватися лише інструментами, які дає harness Ваша система контролю доступу Що проза на кшталт «never delete prod» заблокує інструмент, який усе ще доступний

Це називають галюцинацією. Тут це означає вправні токени там, де мав бути факт або перевірка — вигадані API, вигадані ID тікетів або «тести пройшли». Агент може записати цей винахід у репозиторій. Інструменти зменшують частину цього (вона може зробити grep); вони цього не прибирають.

Токени

Вікно велике — і спільне

Ліміти й вартість — це кількість токенів, а не кількість файлів. Сучасні моделі мають великі вікна: багато сесій Claude Code — порядку 200k токенів; деякі моделі сягають 1M. Цей бюджет — те, що бачить один виклик моделі: ваш промпт досі, файли, які вона прочитала, вивід інструментів і відповідь, яку вона пише — вони ділять лічильник.

Тип~200k токенів вміщують~1M токенів вміщують
Англійська проза ~150 000 слів — коротка книжка ~750 000 слів
Вихідний код порядку 10 000+ рядків, або десятки типових файлів репозиторій середнього розміру одним ковтком
Траси тестів / логи кілька багатослівних дампів pytest можуть забрати велику частку усе одно легко заповнити шумом

Вам не потрібно їх рахувати. Велике — не нескінченне: вона бачить лише те, що ще вміщається в цей виклик.

Ціна

Ви платите за токени, не за файли

Ціна API — це кількість токенів × тариф, опублікований за мільйон токенів. Два лічильники на кожен виклик моделі: input (що цей виклик надсилає моделі) і output (що модель пише назад). Output зазвичай приблизно в п’ять разів дорожчий за input. Більші, сильніші моделі коштують більше за токен. Точні долари змінюються; ця форма — ні.

ЛічильникЩо рахуєЯк рухається вартість
Input Промпт досі, файли, які вона прочитала, результати інструментів, попередні ходи Лінійно від того, наскільки повне вікно цього виклику
Output Відповідь — включно з текстом викликів інструментів Лінійно від того, як довго вона говорить; дорожчий лічильник
Cached input Повторюваний префікс (системний промпт, інструменти) Частка свіжого input, якщо цей префікс не змінився

Кожен крок агента — це новий виклик моделі. Багатослівний дамп pytest — не одноразовий: він є input зараз і знову на наступному ході, доки не випаде з вікна. Тому шумні логи дорогі навіть коли вікно велике.

Claude Code на курсі зазвичай — це підписка, а не сирий API-ключ. Ті самі лічильники все одно крутяться знизу. Упертися в ліміт використання — це впертися в цей бюджет.

«Знати»

Навчання проти цієї сесії — не змішуйте їх

Люди кажуть «Claude знає X» про дві роботи, які в чаті виглядають однаково. Сесія — одна розмова з власним вікном. Постійні знання мають жити у файлах.

Навчання

«Знає Python»

Якщо дати текст, схожий на Python, вона продовжить його Python-кодом, який часто компілюється. Це знання в вагах. Воно переживає кожну нову сесію.

Ця сесія

«Знає наш репозиторій»

Лише після того, як прочитала файли, тікети, помилки та CLAUDE.md. Усередині моделі немає постійної копії вашого репозиторію. Наступна сесія починається без цього чату.

Помирає разом із сесією

  • Діалог, який ви щойно мали
  • Файли, які вона прочитала, але ніколи не записала
  • Стиль, який ви пояснили лише в чаті

Переживає нову сесію

  • CLAUDE.md, rules, skills, документація
  • Тікети й результати MCP, які ви знову отримуєте
  • Історія git, тести, сам репозиторій

«Claude забув наш стиль коду» зазвичай означає «нова сесія, нічого не записали». Лекція 2 — про те, як навмисно перезавантажити корисні частини.

Пастка

Чатбот ставить вас посередині

Чатбот може допомогти написати функцію. Він розвалюється, коли робота — «зробити цей репозиторій правильним». Агент — та сама модель з інструментами: вона викликає їх, читає результати й продовжує, доки завдання не виконано — або доки ви її не зупините.

Чатбот — ви є руками

Ви друкуєте → воно відповідає текстом Ви копіюєте, запускаєте тести, вставляєте помилку Повторюєте, доки не втомитесь

Агент — інструменти є руками

Ви ставите завдання і перевірку Воно читає, редагує, запускає pytest… Ви перевіряєте докази, а не кожне натискання

Цей цикл — зібрати → діяти → перевірити. Спроєктуйте завдання так, щоб воно могло закритися без вас. Якщо немає перевірки, перевіркою стаєте ви.

Перевірити

pytest, ruff, збірка, скріншот — pass або fail. Упало? Цикл. Пройшло? Показати вивід. Застрягло? Запитати вас.

Продукт

Claude Code = модель + інструменти + harness

Без інструментів вона вміє лише говорити. З інструментами текст стає запитами, які виконує застосунок — і лише інструменти, які дав harness. Harness — причина, чому двоє людей з тією самою моделлю отримують різні результати. Стандарт курсу: terminal CLI у папці проєкту.

Harness

Продукт навколо них

Permissions, CLAUDE.md, skills, hooks, compaction, checkpoints, UI. Це ви налаштуєте в Лекції 2.

Інструменти

Руки

Файли, пошук, shell (тести, git, лінтери), веб, субагенти, пізніше MCP (Jira). Claude бачить ім’я, опис і схему — не магічне розуміння Jira.

Модель

Передбачувач

Міркує, пише, обирає, який інструмент викликати далі. Усе ще лише передбачає токени, тепер обумовлені результатами інструментів.

Перший день

Спочатку дослідити, потім визначити «готово»

Меню, а не обіцянка: дослідити, імплементувати зі специфікації, виправити баг, рефакторити за патерном, запускати тести — пізніше git і MCP. Слабкі промпти («виправте тікети») вигадують правдоподібніше «приємніше». Сильні називають файл, контракт, pytest + ruff і вивід.

Дослідити — без правок

Ви в CampusDesk. Не змінюйте жодних файлів.
1. Що робить цей застосунок?
2. Як його запустити і тестувати?
3. Куди додати нове поле на тікеті?

Потім перевірка

Додайте PATCH з @docs/specs/SPEC-001.md.
Напишіть тести з критеріїв приймання.
Запустіть pytest і ruff. Виправляйте, доки не стане зеленим.
Покажіть вивід команд.

Якщо воно починає переписувати README — зупиніть. Покладіть «no edits» у промпт. Звичка: спочатку читати, потім змінювати, завжди вимірювати.

Межі

На цьому воно все одно провалить — і ви все одно спробуєте

Чесність економить години. Агент прискорює середину. Кінці лишаються людськими.

  • Розмитий смак — «зробіть API приємнішим» дає випадкове приємніше. Запишіть це приємніше.
  • Секрети й production — жодних production-облікових даних у чаті; жодних ненаглянутих записів у production Jira.
  • Приватні факти — якщо цього немає в репозиторії, тікеті, MCP чи вебі, вона заповнить прогалину правдоподібним реченням.
  • Величезні хаотичні сесії — після достатньої кількості файлів і stack traces якість падає. Це контекст, не лінь.
  • Політика, записана лише англійською — «Never edit .env» у CLAUDE.md — це прохання. Hook, що блокує правку, — це примус.

Безпека

Permissions — перемикайте через Shift+Tab

Claude Code питає перед багатьма діями, залежно від permission mode. На деяких терміналах Windows скорочення — Alt+M. Починайте з Manual або Accept edits. Користуйтеся Plan, коли завдання — ціла фіча. Не починайте з Bypass, бо слайд виглядав круто.

РежимВідчуттяКоли
ManualПитає перед правками й shellПерші сесії, незнайомі репозиторії
Accept editsВільно править, усе ще питає за ризиковий shellКоли ви довіряєте завданню і папці
PlanЧитає й пропонує, без правок кодуУсе, що стане PR
AutoКласифікатор дозволяє більшість, блокує страшнеПізніше, коли ви знаєте allowlist
BypassМайже без запитівЛише ізольовані середовища

Безпека

Checkpoints — це не git — переривайте, не починайте спочатку

Перед правками файлів Claude Code робить знімок файлів. Подвійний Esc може відкотити розмову й файли. Віддалені побічні ефекти не відкочуються. Коли воно йде не туди, скажіть, що було не так; починайте спочатку, коли змінилось завдання або контекст — сміття.

Checkpoints можуть скасувати

Локальні правки файлів у цій сесії. Корисно, коли підхід хибний і ви хочете файли назад.

Checkpoints не можуть скасувати

Переходи в Jira, git push, видалені таблиці, усе, що покинуло ноутбук. Git — справжнє скасування для комітів. Permissions і hooks — справжнє скасування для інструментів, що виходять за межі машини.

  • Esc — зупинити цей хід. Наберіть виправлення, поки воно працює.
  • Відхиліть виклик інструмента, якщо команду не варто запускати.
  • Режим Plan, коли завдання — зміна розміру PR.

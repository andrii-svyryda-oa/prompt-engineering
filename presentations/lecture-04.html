Lecture 4

Model context, and how to manage it

Why the agent got fuzzy at 4pm — and the commands that clean the desk.

Today

Six things you should leave with

  1. The window is RAM for this conversation, not a hard drive for the repo. The repository stays on disk. Claude can re-read a file. It cannot magically remember a paragraph that was summarized away unless that paragraph lives in a file.
  2. /context is how you see the pie — and you already paid before “hi.” Memory files, skill descriptions, and MCP names tax every session. A 400-line CLAUDE.md that imports the wiki is why people say Claude ignores rules. The rules are in there. They are buried.
  3. Tool output is the silent killer. Fifteen lines of a pytest failure is gold. A 2,000-line dump is poison. Re-reading the same files and mixing side quests into a feature session shoves the spec into the fog.
  4. Compaction is automatic, lossy, and necessary. The gist stays. The third acceptance bullet may not. Durable rules belong in files. After compact, @ the spec again if the task continues.
  5. Four resets, four jobs. /compact for the same task with a fat window. /rewind when the approach was wrong. /clear when the next task is unrelated. A new session (or -c) for a new day.
  6. Notice a sick window before the code rot is obvious. Ignored spec bullets, reinvented helpers, a new style, looping on the same log. Then a protocol: clean session per spec, Plan mode, quiet tests, side quests elsewhere.

The constraint

Almost every best practice is a context practice

The model in a nearly full window is not a different product. It is the same product with a messy desk. It will drop a constraint from the spec, “forget” the linter rule, or hallucinate a function it read an hour ago.

You will learn to see the window (/context), spend it on purpose, reset it (/compact, /clear, /rewind), and isolate heavy reads (skills, subagents, path-scoped rules).

Definition

Working memory of this session

The context window is RAM for this conversation, not a hard drive for the repository.

It is the maximum tokenized text the model can attend to in one request: system prompt, tools, memory files, your messages, file contents, command output, MCP results.

  • Many sessions: on the order of 200k tokens. Some models: up to 1M.
  • A million is not infinite. One fat Jira payload + twenty reads + verbose pytest + MCP names, and a 200k window is in trouble.
  • Quality often drops before the hard limit. Attention to the middle fades. Compaction may already have summarized away the spec.

Fill rate

A realistic CampusDesk hour

None of these are mistakes individually. Together they shove the spec into the fog.

  1. Attach a spec (~3k tokens)
  2. Read models, store, main, tests
  3. Verbose pytest -vv dump
  4. Traceback, then a screenshot (images are tokens too)
  5. Re-read docs/product.md “just to check”
  6. An unrelated git question in the same session — launched from the course root by mistake

Tool output is the silent killer. Put in CLAUDE.md: run pytest -q unless debugging a single test. Say “you already have store.py” instead of letting it read it again.

Compaction

Automatic, lossy, necessary

When the window approaches its limit, Claude Code asks the model to summarize older conversation and continues with that summary plus a fresh working set. Lifesaver. Also data loss.

Usually comes back

System prompt. Root CLAUDE.md and unscoped rules, re-read from disk. Plan file. Auto memory. Maybe a few recent files. Skill bodies, maybe, with caps — important lines at the top.

Often gone

The third acceptance bullet. Your exact early prompt (maybe one sentence). Hook output from an hour ago. A file it read once and never wrote down.

Durable rules belong in files, not in message 2. If the task continues, @ the spec again after compact.

Manual compact

Tell it what to keep

A focused compact is better than the automatic pass, which guesses what matters. You can also change when autocompact fires, on versions that support it.

/compact focus on SPEC-001
         and the failing tests

/rewind can summarize part of the conversation so you keep the tail intact.

Four resets

Different jobs. Do not swap them.

People /clear too late (the feature is already polluted with a side quest) or /compact when they should /clear (the summary still talks about the side quest).

Lean by design

Lecture 2, seen from the token side

The default session should be cheap enough that “rename this variable” is not paying for the wiki.

  • CLAUDE.md under ~200 lines
  • Path-scoped rules instead of one giant always-on file
  • Skills for long playbooks — description now, body on demand
  • Mention doc paths instead of importing encyclopedias
  • Disconnect unused MCP servers
  • Subagents for wide research; parent session gets the summary
  • cd into CampusDesk — not the course root

Symptoms

Notice the sick window before the PR is wrong

Sick window

  • Ignores a spec bullet it agreed to an hour ago
  • Reinvents a helper that already exists
  • Suddenly uses a new style
  • Loops on the same log

Moves

  • @ the spec again
  • /context — what is actually in there?
  • Compact with a focus, or clear if the job changed
  • Extract 20 lines of failure; do not cat the log
